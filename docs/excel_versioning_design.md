# Excel Versioning Design

## File Naming Convention

Format:
```
Finco1_{ProjectType}_{Scenario}_{YYYY-MM-DD}_{HHMMSS}.xlsx
```

Examples:
- Finco1_Solar_Base_2026-05-04_143000.xlsx
- Finco1_Wind_Downside_2026-05-04_090521.xlsx

## Version Tagging

Every exported Excel contains a `Notes` sheet with:

| Field | Value |
|---|---|
| Model Version | industry-engine-refactor |
| Git SHA | 9ffbc2d |
| Run Timestamp | 2026-05-04 14:30 UTC |
| Scenario | Base |
| Export Format | Values-only (no formulas) |

## Metadata Sheet Content

A dedicated `Metadata` sheet is recommended for formal releases:

| Field | Value |
|---|---|
| File Name | Finco1_Solar_Base_2026-05-04.xlsx |
| Model Version | industry-engine-refactor |
| Git SHA | 9ffbc2d |
| Generated At | 2026-05-04 14:30 UTC |
| Generated By | Finco1 Streamlit App |
| Scenario | Base |
| Project Type | Solar |
| Validation Status | Unvalidated / Validated |

## Reproducibility Strategy

1. **Git commit is source of truth**: Every export can be traced to a git SHA
2. **Inputs snapshot**: ProjectInputs are serialized in Notes/Inputs sheet
3. **Deterministic runs**: Same inputs + same code = same output (no RNG)
4. **Archive**: Old exports stored in `exports/{YYYY-MM}/` folders

## Version Comparison

Future (Phase 3):

## Backward Compatibility

- Excel format (xlsx) is stable — no plan to switch to xlsb
- Sheet order may change — always reference by sheet name, not position
- New sheets may be added — code should handle missing sheets gracefully
