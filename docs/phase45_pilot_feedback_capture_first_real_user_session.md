## 7. Feedback Session Workflow

1. **Operator prepares** — reviews `docs/pilot_real_user_session_agenda.md`
2. **Scope briefing** — user acknowledges `docs/pilot_scope_confirmation_note.md` before starting
3. **Task observation** — operator observes user attempting TUHO and Oborovo workflows
4. **Feedback captured** — operator fills `docs/pilot_feedback_form_template.md` during or after session
5. **Session notes** — operator fills `docs/pilot_first_real_user_session_notes_template.md`
6. **Triage** — feedback routed via `docs/phase45_pilot_feedback_triage_matrix.md`
7. **Issue intake** — any issues filed via `docs/pilot_issue_intake_template.md`

---

## 8. Success Criteria (Controlled Trusted Pilot)

The controlled trusted pilot is considered successful if a real user can:

- Select TUHO or Oborovo project without confusion
- Save a named scenario before changing inputs
- Run the model and interpret the runtime summary correctly
- Distinguish draft edits from the last clean backend run
- Export results and understand they reflect the last clean run
- Use the Audit/Parity tab as internal review evidence
- Correctly identify generic solar/wind as unvalidated
- Not make external claims (bank/lender/audit/certification)

---

## 9. Blocker Criteria

A real-user session produces a blocker if the user:

- Cannot complete a TUHO or Oborovo run without error
- Misinterprets stale exports as current outputs
- Treats generic solar/wind as validated for financial decisions
- Makes external claims (bank/lender/audit/certification) based on pilot outputs
- Is unable to distinguish draft/saved/runtime state despite explanation
