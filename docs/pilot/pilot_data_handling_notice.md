# Pilot Data Handling Notice

This file is the **pilot data handling notice** for the
controlled internal pilot. It is a companion to the B21 pilot
user acknowledgement and the B7 pilot user feedback protocol.
It describes how pilot data is collected, stored, retained,
and disposed of during and after the pilot.

> **Pilot data is internal evidence. It is not external
> validation, not a customer reference, and is not used in
> any marketing or sales material without the pilot user's
> explicit written consent.**
>
> **This is not a legal contract.** It is an internal data
> handling notice. The project lead assigns actual personnel
> and any contractual terms separately. This document does
> not give legal advice.
>
> **Claude review is separate.** The Phase 51N checkpoint
> includes a Claude review preparation pack on the Agent A
> side; Claude review itself is handled outside this branch.

---

## 1. What is pilot data

Pilot data is the data collected during the controlled
internal pilot. It includes:

* **Pilot user input** — the data the pilot user enters into
  the model during the pilot run (e.g. project parameters,
  scenario overrides).
* **Run logs** — start time, end time, run-time warnings,
  model output.
* **Validation records** — expected vs observed, per metric.
* **Exports** — Excel files generated by the model.
* **Screenshots** — when they document something the run
  logs do not.
* **User feedback** — the pilot user's anonymized feedback.
* **Issue log entries** — per the B7 pilot issue triage
  process and the B20 issue log template.
* **No-go acknowledgements** — signed by the pilot user and
  operator.
* **Pilot user identification data** — the pilot user's
  real name, role, and contact information (stored
  separately from the anonymized evidence).

## 2. Allowed data

The pilot uses:

* **TUHO inputs** (the then-inline / now-frozen reference
  template).
* **Oborovo inputs** (the then-inline / now-frozen reference
  template).
* **Pilot user inputs** (anonymized).
* **Internal test inputs** (the validation/cases/ inputs).

## 3. Prohibited data

The pilot does **not** use:

* **Production data.**
* **Customer data.**
* **NDA-protected data.**
* **External model outputs** (no claims based on third-party
  model results).
* **Personal data** beyond what is necessary for the pilot.

## 4. Data isolation

Pilot data is **isolated** from production data, customer
data, and NDA-protected data. The isolation is enforced at
three levels:

* **Environment level.** The pilot runs in a separate
  environment from the production environment. The
  environment is isolated at the network, file system, and
  database level.
* **Process level.** The pilot operator does not have access
  to production data. The pilot user does not have access to
  production data. The B-track owner does not have access to
  production data.
* **Data manifest level.** The data manifest (per the B7
  runbook §2) records the exact data loaded into the pilot
  environment. The manifest is signed by the pilot operator
  before the pilot starts.

A data isolation breach is a `pilot-blocker` issue and
triggers a pilot stop.

## 5. Anonymization

Pilot user input is **anonymized** for evidence-tagging
purposes. The anonymization is:

* **Pilot user ID** — a unique identifier assigned by the
  pilot operator (e.g. `PU-2026-Q3-001`). The pilot user's
  real name, role, and contact information are stored
  **separately** in a controlled access list, not in the
  evidence itself.
* **Pilot operator ID** — a unique identifier assigned by
  the project lead (e.g. `PO-2026-Q3-001`). The pilot
  operator's real name, role, and contact information are
  stored separately in a controlled access list, not in the
  evidence itself.
* **Project lead ID** — a unique identifier assigned by the
  project lead (e.g. `PL-2026-Q3-001`). The project lead's
  real name, role, and contact information are stored
  separately in a controlled access list, not in the
  evidence itself.

The anonymization is enforced at the data capture level.
The pilot user input is captured with the anonymized
identifier, not with the real name.

## 6. Storage

Pilot data is stored in the pilot-only location defined in
the pilot scope. The storage is:

* **Encrypted at rest** — using the storage provider's
  encryption.
* **Encrypted in transit** — using TLS for all data
  transfers.
* **Access-controlled** — only the pilot operator, the
  project lead, the B-track owner, and the pilot user (for
  their own input) have read access.
* **Audit-logged** — every access is recorded for the
  duration of the retention period.

## 7. Retention

The default retention is **the duration of the pilot run
window plus 90 days**. After the retention period expires:

* Pilot data is **deleted** from the storage location.
* Pilot data is **deleted** from any backups.
* Pilot data is **not archived**.

The project lead may specify a different retention period in
the pilot scope document. A shorter retention period is
permitted (e.g. 30 days after the pilot closes). A longer
retention period is permitted only with the project lead's
explicit written approval and a documented rationale.

## 8. Sharing

Pilot data is shared with the following parties:

* **The pilot user** — for the pilot user's own input and
  the pilot user's own user feedback.
* **The pilot operator** — for the pilot operator's
  operational responsibilities.
* **The project lead** — for the project lead's oversight
  responsibilities.
* **The B-track owner** — for the B-track governance
  refresh.
* **The third-party reviewer** (if and when the third-party
  review is performed) — bound by the no-go claim list and
  the reviewer's acknowledgement.
* **Claude review** — **NOT** shared with Claude review.
  Claude review is separate and is not represented in this
  branch.

Pilot data is **not** shared with:

* Any external party not listed above.
* Any marketing or sales team.
* Any customer (the project does not currently have
  customers).
* Any investor, partner, or other stakeholder not listed
  above.

## 9. Disposal

After the retention period expires:

* Pilot data is **deleted** from the storage location.
* Pilot data is **deleted** from any backups.
* Pilot data is **not archived**.
* The deletion is **logged** (timestamp, who deleted, what
  was deleted).
* The deletion is **irreversible** — there is no way to
  recover the pilot data after the deletion is performed.

## 10. What this notice is not

* It is not a legal contract. The paid pilot user agreement
  is the contract (separate document; not this one).
* It is not external validation. The pilot data is internal
  evidence.
* It is not a customer reference. The pilot user is not a
  customer.
* It is not a substitute for the B21 pilot user
  acknowledgement or any other B-track governance artifact.
* It is not paid pilot authorization. The paid pilot gate
  (B13) is a separate stage.
* It is not Claude review. Claude review is separate.
