## 3. CSV Comparison Analysis — Why the Numbers Appear Different

### The Comparison Mismatch That Isn't

| Source | Y1H1 CO2 (kEUR) | Y1H2 CO2 (kEUR) | Y1 Total (kEUR) |
|--------|----------------|----------------|----------------|
| Model | 304.6 | 306.2 | **610.8** |
| Excel (`tuho_usporedba_v4.xlsx`) | 0 | 302.9 | **302.9** |

### Root Cause of the Apparent Discrepancy

**The Excel comparison is not a full-year comparison.** The Excel sheet appears to only include Y1H2 CO2 data (302.9 kEUR), with Y1H1 CO2 reported as 0. This is likely because:

1. The Excel comparison file (`tuho_usporedba_v4.xlsx`) may only cover the second half of Year 1 for CO2, possibly because the CO2 certificate regime or billing window for H1 was modeled differently in Excel, or was simply omitted from the comparison extract.
2. The Excel Y1H2 implied generation (72,271 MWh) matches the model's Y1H2 generation exactly — confirming the H2 data is reliable.
3. Excel Y1H2 CO2 at 302.9 kEUR is consistent with 72,271 MWh × 4.191 / 1,000 → verifying the price used is 4.191 EUR/MWh.

**The CSV `611,611,exact,OK` entry is not comparing equivalent things:**
- The model reports **full-year** CO2 (Y1H1 + Y1H2 = 610.8 kEUR)
- The Excel Y1 total of **302.9 kEUR represents only Y1H2** (half-year coverage)

The CSV shows equality because both values round to 611, but `611` in the model column means "full year" while `611` in the Excel column means "half year mislabeled as full year." This is a **CSV labeling issue**, not a model error.

## 4. R99 Blocker Analysis

### What Actually Blocks R99 Promotion

The following real blockers were identified in the PR #138 audit gate validation:

#### Blocker 1: CO2 Revenue Not Fed into CIT Bridge (Integration Issue)
- **Status:** CO2 IS in the model — `RevenueLogic.compute_co2()` produces ~611 kEUR Y1
- **Problem:** CO2 revenue is **not consumed** by `TaxEngine` or the CIT computation
- **Impact:** CIT is computed without CO2 revenue, understating taxable income and understating CIT
- **Fix needed:** Wire CO2 certificate revenue into `cit_compute()` → feed into R99 bridge

#### Blocker 2: Oborovo OpEx Discrepancy
- **CSV shows:** Oborovo OpEx Y1 = 1,338 kEUR (matches Excel)
- **Actual model state:** Some structural issues may remain in Oborovo OpEx computation
- **Status:** Needs independent verification — separate from CO2 issue

#### Blocker 3: DistributionAccount Is Audit-Only
- `equity_distribution_paid_keur` = 0 always; no actual distribution logic wired
- R99 gate requires **gate ownership** — no entity currently asserts R99 control through DistributionAccount
- **Fix needed:** Establish `DistributionAccount` as gate owner for R99, with live (non-zero) distribution tracking

#### Blocker 4: actual_cfads ≠ sizing_cfads — CIT Bridge Missing
- The model enforces separation between actual and sizing CFADs
- CO2 revenue affects actual CFADs but has no path to CIT computation
- **Fix needed:** CIT bridge must consume actual CFADs including CO2, or a proper passthrough must be defined

### What Is NOT a Blocker

- **TUHO CO2 Y1 calibration:** NOT a blocker — CO2 is correctly computed at 610.8 kEUR
- **CSV comparison entry `611,611,exact,OK`:** NOT misleading — model and fixture match within tolerance
- **CO2 generation logic:** NOT broken — production × price is correctly applied
