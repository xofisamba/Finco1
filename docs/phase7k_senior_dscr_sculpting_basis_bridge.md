# Phase 7K Senior DSCR Sculpting Basis Bridge

## Purpose

This bridge isolates the remaining senior principal and debt-service gaps after
the senior rate/day-count path proved first-period interest parity for TUHO and
Oborovo.

No runtime behavior is changed. The senior rate schedule engine remains
default-off, project factories are not opted in, senior opening debt remains
principal-only, and SHL `fcf_waterfall` is not implemented.

## Current Baseline

Confirmed before this bridge:

- operating senior debt opens on principal only,
- senior IDC is excluded from operating senior debt,
- commitment fees are excluded from operating senior debt,
- rate/day-count can reproduce first-period senior interest when enabled with
  explicit fixture inputs,
- remaining senior debt gap is mainly principal / sculpting basis.

## Python Sculpting Path

Python still uses the existing waterfall senior debt architecture:

- opening senior balance is `fixed_debt_keur` when debt sizing is fixed,
- rate/day-count fixture feeds only the existing per-period `rate_schedule`,
- senior sculpting / repayment formulas remain unchanged,
- principal is generated by the existing sculpted schedule and final repayment
  logic,
- SHL, revenue, OPEX, tax, R99, sponsor waterfall, and construction
  capitalization are unchanged.

## Root-Cause Candidates

| Candidate | Finding | Confidence |
|---|---|---|
| Interest rate / day-count | Mostly isolated. First-period interest now matches Excel under explicit fixtures. | High |
| Senior opening balance | Not the cause. Principal-only policy remains aligned. | High |
| Senior IDC / fees capitalization | Not the cause. Excluded from operating senior debt in both Excel and Python. | High |
| CFADS timing | Not first-order in period 1. Prior bridge showed first-period CFADS is close for both projects. | Medium |
| DSCR sizing basis | Likely contributor. Excel principal formulas reference specific DS rows and input multipliers rather than Python's current sculpting basis. | High |
| Repayment timing / period shape | Likely contributor. Early Python principal is too low and final repayment too high. | High |
| Reserve account timing | Possible contributor, especially if Excel senior DS basis includes reserve releases/funding differently. | Medium |
| Discounting / amortization boundary | Possible contributor to final repayment shape. | Medium |
| Final repayment cap logic | Confirmed symptom, but not enough evidence for a standalone fix. | Medium |

## Is A Runtime Sculpting Fix Justified?

Not yet.

The evidence proves the remaining gap is principal/sculpting, but it does not
yet prove one safe formula change for both TUHO and Oborovo. A runtime fix would
need to establish:

1. the exact Python equivalent of Excel's senior DS basis rows,
2. whether reserve movements are included before or after DSCR sizing,
3. whether repayment timing is beginning-of-period or end-of-period equivalent,
4. whether final-period repayment is intentionally shaped or just residual,
5. whether the same convention applies to TUHO and Oborovo.

## Recommendation

Do not change runtime senior sculpting yet.

Next branch:

```text
phase7k-senior-dscr-sculpting-runtime-design
```

Scope should be a design document for a default-off senior sculpting basis
configuration, using the existing senior debt engine where possible and
preserving legacy behavior. It should explicitly avoid SHL `fcf_waterfall`,
revenue, OPEX, tax, R99, sponsor waterfall, construction capitalization, UI, and
cache changes.
